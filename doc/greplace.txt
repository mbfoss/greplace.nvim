  WORK IN PROGRESS
Project-wide search and replace by editing the grep results.

>
    :Gsearch <query>
<

greps the working tree and collects every matching line into a split named
`greplace://greplace-matches`. Each line is the matched line itself, as plain
editable text. The `file:line` in front of it is virtual: it cannot be typed
over, and it tells the plugin where the line came from.

Edit the lines however you like (`:%s/…`, visual block, macros) and write the
buffer:

>
    :w
<

Every changed line is written back to its source **in memory**: open files keep
their buffer, other files are loaded into one. Nothing is written to disk, so
the change is one `:wa` away, or one `u` per buffer from being undone. `u` in
the panel undoes the write there too, and writing again reverts the source.


  **Requires Neovim ≥ 0.11** and ripgrep
  <https://github.com/BurntSushi/ripgrep> on `$PATH`. No plugin dependencies.

1. Installation                                        *greplace-installation*

**lazy.nvim**

>lua
    {
      "mbfoss/greplace.nvim",
      config = function()
        require("greplace").setup()
      end,
    }
<

`setup()` is optional; the commands register themselves and nothing is loaded
until one is first run.

2. Usage                                                      *greplace-usage*

  -----------------------------------------------------------------------
  Command                             Effect
  ----------------------------------- -----------------------------------
  :Gsearch foo bar                    literal search for foo bar
                                      (smart-case)

  :Gsearch --hidden -- foo            the same search with flags; see
                                      below

  :Gsearch                            with nothing at all: cancel the
                                      search still running

  :'<,'>Gsearch                       search for the visual selection;
                                      see below

  :Greplace                           put the panel back on screen
                                      (:Greplace open)

  :Greplace close                     take it off again, keeping the list
                                      in it

  :Greplace toggle                    one or the other, whichever it is
                                      not

  :Greplace qf                        fill the panel from the quickfix
                                      list instead of a search

  :Greplace refresh                   run the list’s search again (!
                                      discards unapplied edits)

  :Greplace diff                      preview what writing the panel
                                      would change, as a diff

  :Greplace apply                     apply the panel’s edits, as :w in
                                      it does
  -----------------------------------------------------------------------
Everything after `:Gsearch` is the query, searched literally: quotes,
backslashes and leading dashes included. It is split by Vim’s own rules
(|<f-args>|), so each space inside the query is written `\` and a literal
backslash `\\`; any other backslash (`\d`, `\s`) stands for itself. A regex,
case rule or narrowed file set is asked for with flags, below.


:GREPLACE: THE PANEL                                          *greplace-panel*

`:Greplace` never searches. `open`, `close` and `toggle` show and hide the
panel; the buffer stays, so showing it again brings back the same list and any
unapplied edits. The subcommands tab-complete, and there is nothing to show
until a search has filled the panel once.

`refresh` runs the list’s search again with the same query, flags and root; a
list from `:Greplace qf` is refilled from the quickfix list. A panel with
unapplied edits is left alone: write them first, or use `:Greplace! refresh` to
discard them.

`diff` shows what `:w` would do: every file with an edited match, as a unified
diff on a tab of its own; `q` closes it. It works on copies, so nothing is
applied and no file is loaded. An open file is diffed from its buffer, unsaved
changes included. An edit the write would skip, because its source line has
changed since the search, is listed at the top.

`apply` is `:w` in the panel, from wherever you are. Either one closes the
preview, which is out of date once the edits have landed.


:'<,'>GSEARCH: SEARCHING FOR THE SELECTION                                 *greplace-selection*

Given a range, `:Gsearch` takes its query from the buffer. Select text and
press `:`, and the selection is searched for literally, with no escaping. With
a linewise selection, or a typed range (`:.Gsearch`, `:12Gsearch`), the query
is that whole line, trimmed of indentation and trailing blanks.

The range must stay on one line, since ripgrep matches line by line. Flags may
follow, and the selection becomes their query, so `--` is optional and nothing
may come after it:

>
    :'<,'>Gsearch --type lua --word
<

A mapping makes it one key:

>lua
    vim.keymap.set("x", "<leader>s", ":Gsearch<CR>", { desc = "greplace: search selection" })
<


:GSEARCH --FLAGS: SEARCHING                                   *greplace-flags*

A `:Gsearch` line that opens with `--` is a flag line: flags first, then a bare
`--`, then the query.

>
    :Gsearch --glob *.lua --glob !*_spec.lua --hidden -- handle_event
    :Gsearch --type md --dir docs -- TODO
    :Gsearch --regex --word -- ^fn\s+\w+
<

A query that itself starts with `--` goes after a bare separator: `:Gsearch --
--hidden`. Nothing after the first bare `--` is read as a flag. A flag line
without one, an unknown flag, or a value flag left without a value is reported
rather than searched.

The whole line is split by the same rules as the query: `\` is a space inside a
word (`--dir my\ src`, `-- two\ words`), and quotes are not special. Flags are
written `--switch`, `--key value` or `--key=value`, and a repeatable flag is
repeated rather than given a list.

Flag names and values tab-complete: `--type` against `rg --type-list`, `--dir`
against directories. A switch already on the line drops out of the candidates,
and nothing completes past the `--`.

  -----------------------------------------------------------------------
  Flag                                Effect
  ----------------------------------- -----------------------------------
  --dir <path>                        search root (default: the working
                                      directory)

  --glob <glob>                       glob filter, repeatable: *.txt,
                                      !*.lua, **/dir/**

  --iglob <glob>                      the same, matched regardless of
                                      case

  --type <name>                       rg file type, repeatable: lua,
                                      rust, !md (see rg --type-list)

  --max-depth <n>                     maximum directory depth to descend

  --regex                             treat the query as a regex

  --case / --nocase                   case-sensitive / -insensitive
                                      (default: smart case)

  --word / --line                     match whole words / whole lines
                                      only

  --invert                            collect the lines that do not match

  --hidden                            include hidden files (dotfiles)

  --no-ignore                         ignore .gitignore / .ignore rules

  --follow                            follow symlinks
  -----------------------------------------------------------------------
Raw ripgrep arguments are not passed through, by design: a shown line must be
the source line byte for byte, and `--replace`, `--only-matching`, `-l`,
`--count` and `-A/-B/-C` all break that.

File-selection flags are also applied to open buffers, in-process, since
ripgrep sees them as one nameless stdin stream. `--glob` and `--iglob` mean
what they do in ripgrep (`--glob *.lua` leaves out `A.LUA`, `--iglob *.lua`
takes it in), on disk and in buffers alike.

Files open in a buffer with unsaved changes are searched from that text, so the
matches are the ones a write would land on. A location is marked with `≡`
whenever its file is open in a buffer, saved or not.


:GREPLACE QF: QUICKFIX IMPORT                                    *greplace-qf*

`:Greplace qf` fills the panel from the quickfix list as it now stands, so
whatever put entries there (`:grep`, `:vimgrep`, LSP references) becomes an
editable, writable list.

Only the file and line of each entry are used; the line is read back from the
file, or from its buffer when it has one. Entries with no file, no line number,
or an unreadable line are skipped, with a note saying how many. Several entries
on one line are listed once, since the panel edits lines and would otherwise
apply the edit twice.


MAPPINGS                                                    *greplace-keymaps*

  -----------------------------------------------------------------------
  Key                                 Effect
  ----------------------------------- -----------------------------------
  <CR>                                open the source of the line under
                                      the cursor, at that line and
                                      column, keeping the cursor in the
                                      panel

  K                                   show the match under the cursor in
                                      a floating window: its full path,
                                      relative path, line number, whether
                                      it is already loaded in a buffer,
                                      and the source line as the panel
                                      rendered it

  ]c                                  move to the next edited line

  [c                                  move to the previous edited line
  -----------------------------------------------------------------------
The file opens in a regular window, never over the panel, so `j<CR>` steps
through the matches. Set `keys.open` or `keys.hover` to another key, or to
`false`, to change or drop a mapping.

`]c` and `[c` step through the lines marked `•` and take a count (`3]c`); a
count past the last edit stops there. Each is a jump, so `''` and `<C-o>` come
back. They are fixed, not configurable.

The `file:line` column is capped at `path_width` display cells and cropped on
the left; `K` shows the whole path.


EDITING RULES                                               *greplace-editing*

The anchor in front of a line owns that line, which makes the obvious edits
mean the obvious thing:

- **change the line** → the source line is rewritten
- **delete the line** (`dd`) → that match is dropped: its source line is left
    exactly as it is
- **add a line** (`o`, a linewise `p`, `<CR>` mid-line, `:s/x/\r/`) → the line
    is taken out again, with a warning
- **join two lines** (`J`, a charwise delete across a line break, `<BS>` at the
    start of a line) → they are split back apart, with a warning
- **empty the panel** (`ggdG`) → nothing is changed at all

Deleting lines narrows a result set to the matches you want to replace; it
never removes anything from a file. The dropped line’s `file:line` goes with
it, and `u` brings both back.

A match stays one line in the panel: the line break comes back, the cursor
stays where it was, and in Insert mode you stay in Insert mode. What the change
deleted along with the break stays deleted, and `u` brings it back. The space
`J` inserts goes with the join.

An edited line is marked with a `•` in front of its `│`.

A line whose source has moved since the search (an edit elsewhere, a reload) is
left untouched and reported as skipped. After a write the edited markers clear
and the entries take the applied text.

3. Configuration                                      *greplace-configuration*

>lua
    require("greplace").setup({
      height     = 15,    -- height of the result split
      limit      = 10000, -- maximum matches collected per search; a search that
                          -- hits it says so in the winbar
      winbar     = true,  -- show the panel's counts in a winbar
      path_width = 60,    -- greatest width of the `file:line` column, in cells
      spell      = false, -- spell check the panel's buffer
      keys = {
        open  = "<CR>", -- open the source of the line under the cursor
        hover = "K",    -- show the full details of the match under the cursor
      },
    })
<

4. Health                                                    *greplace-health*

>vim
    :checkhealth greplace
<

Reports ripgrep, the commands and the options that differ from the defaults. A
missing ripgrep is an error; an option name greplace does not define is a
warning, since `setup()` would otherwise accept a misspelling in silence.
